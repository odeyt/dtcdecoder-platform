# Capacitor Android Shell — Setup Notes

Scaffolded 2026-08-16. Context and remaining blockers before a real Play Store submission are in [docs/CAPACITOR_NATIVE_APP_READINESS_AUDIT.md](./CAPACITOR_NATIVE_APP_READINESS_AUDIT.md) — read that first if you haven't.

## What this is

`android/` is a native Android (Gradle) project generated by `npx cap add android`. It is **not** a bundled/offline copy of the app — this app is a fully server-rendered Next.js 16 app (API routes, Edge middleware, server actions) that can't be statically exported, so the shell loads the live deployment directly instead of local web assets.

`capacitor-www/index.html` is an unused placeholder. Capacitor's `cap add`/`cap sync` require a `webDir` to exist on disk even when `server.url` is set — this file exists only to satisfy that, it is never actually loaded by the app.

## Configuration

`capacitor.config.ts` (repo root):

| Setting | Value | Why |
|---|---|---|
| `appId` | `com.dtcdecoder.app` | Reverse-domain of dtcdecoder.com. **Permanent once published to Play Console** — do not change without understanding the consequences (a new appId is a new app listing). |
| `appName` | `DTCDecoder` | Shown under the home-screen icon. |
| `server.url` | `https://dtcdecoder.com` | The native shell is a WebView pointed at production, not a local bundle. |
| `server.cleartext` | `false` | Matches the app's own HTTPS-only posture (see `next.config.ts`'s HSTS header) — no plaintext `http://` loads. |
| `server.androidScheme` | `https` | Keeps the WebView's origin scheme as `https`, matching Supabase cookie `Secure` attribute expectations. |

`android/variables.gradle`: `minSdkVersion 24` (Android 7.0+), `targetSdkVersion 36` (current Capacitor default) — both are the generator's defaults, not yet deliberately tuned for this app's actual audience.

## What's NOT done yet

This is scaffolding only — the project structure and config exist, and it now builds successfully, but none of the following has happened:

- **Never installed/run on an emulator or device.** A debug APK exists but hasn't actually been launched to confirm the WebView loads correctly, sign-in works, or a diagnostic report renders.
- **No app icons.** Capacitor's default placeholder icon/splash assets are in place; the PWA icons already exist at `public/icons/icon-192.png` / `icon-512.png` but haven't been run through Capacitor's asset generator (`@capacitor/assets`) to produce the full Android mipmap/adaptive-icon set.
- **No push notifications, native camera, or other native-only features** — per the readiness audit, at least one of these is likely needed to satisfy store minimum-functionality review (more relevant on iOS than Android, but still worth building for both).
- **No deep-link config** (App Links / `assetlinks.json`) — magic-link sign-in and any Creem checkout return URL still resolve to `https://dtcdecoder.com/...`, which will open the system browser instead of this app unless App Links are set up. Password sign-in (already live) is the safe default inside this shell in the meantime.
- **No signing keystore** — a debug build will use Capacitor/Gradle's default debug signing; a real release keystore has to be created and kept out of the repo (`android/.gitignore` already excludes `local.properties`, build outputs, and other generated files, so no secrets have leaked from this scaffolding step).
- **Never synced against a real device or emulator.**

## Next steps to actually run this

1. Install Android Studio (includes the SDK, an emulator, and Gradle tooling).
2. `npm run android:open` (runs `cap open android`) to open the project in Android Studio.
3. Run on an emulator or a physical device over USB debugging.
4. Confirm the WebView loads `https://dtcdecoder.com`, sign-in via password works, and a diagnostic case can be viewed end-to-end.
5. Only after that: work through the readiness audit's remaining items (push notifications, native camera capture, App Links, icons) before considering a Play Console submission.

## Keeping this in sync

Whenever `capacitor.config.ts` changes, run `npm run cap:sync` to propagate it into `android/app/src/main/assets/capacitor.config.json` — `cap add` already ran this once, but it does not happen automatically on every edit.
